# purpose
- how code and files fit together

## structure
### One-paragraph summary — what the project does, in plain terms.

### Entry point — literally the file and function to open first (src/main.rs, fn main, or lib.rs).

### Reading order — a numbered path: "1. read X, then Y, then Z." This is the most valuable part and the thing READMEs rarely have.

### Module map — a short tree or table of directories and what each is responsible for.

### Key types/objects — the 3–7 central structs/enums/traits and how they relate (a small ASCII diagram helps a lot).

### Data/control flow — how a request/call/event moves through the system.

### "Where to look if…" — a cheat sheet: "Adding a new command → src/cli/commands.rs", "Changing config parsing → src/config.rs".

### Glossary (optional) — domain terms.
